# 설계 — 입체교차 (교차로 4형제 완성, 엔진분)

> 작성: 2026-07-12 (환 자율 위임 — 로드맵 2026-07-12 확정분, 자율 설계·결정 근거 명기). 짝 계획: writing-plans로 후속.
> 선행 스택: 회전교차로(`feat-roundabout-hwan`, EditMode 142) 위. 브랜치 `feat-overpass-hwan`.
> 배경: 로드맵 "1차 빌드 확장 ②입체교차 엔진분" — 회전교차로 배치 인프라 재사용, 교차로 4형제(무신호/신호/로터리/입체) 완성. 고가 그래픽은 에셋 단계 후속, 이번엔 마커 수준.

## 목표 / 스코프

**입체교차 = 교차로에 배치하는 넷째 상태.** 두 축이 위아래로 분리돼 **간섭이 소멸**한다: `ratioH = 가로/용량, ratioV = 세로/용량` (합산도, λ도, 듀티도, 페널티도 없음). 엔진(수식+배치 API+세이브) + 최소 마커까지 이번 범위. 가격·상점 UI는 팀 몫(로터리와 동일 분업). 차량의 위/아래 통과 연출은 에셋 단계 후속(비목표).

## 핵심 결정 (근거 포함)

| 결정 | 내용 | 근거 |
|---|---|---|
| **수식 = 축 완전 독립** | 기본 도로 규약(합산 `(fH+fV)/C`)을 교차로에서 축별 `fH/C`·`fV/C`로 대체 | "겹치지만 서로 간섭하지 않는 독립 ratio" — 로드맵·원기획 그대로. 신호 g=1을 양축에 동시에 준 것과 동치 |
| **상위호환은 의도** | 입체교차는 신호·로터리·무신호를 수학적으로 항상 이긴다(어떤 흐름 조합에서도 ratio 최소) | action-system의 "비싼 천장" 포지션 — 전략 선택이 아니라 재화 소모처. 균형추는 가격(진우 협의). 로터리(3분할 전략템)와 역할이 다름을 주석에 명기 |
| 상태 표현 = 배치 리스트 병렬 | `_placedOverpasses` — 로터리와 동형 3벌째 | 검증된 패턴. **단 이번이 3벌째 복붙** — "두 번까진 복붙, 세 번째부터 추상화" 기준 발동. 아래 "배치물 공통화" 결정 참조 |
| **배치물 공통화는 이번에 안 함** | 신호는 조율값(Signal 객체·SignalMap 연동)이 있어 로터리/입체(좌표만)와 구조가 다름 — 좌표-전용 배치물 2벌만으론 공통화 이득이 얇다 | 티어2 일방통행·턴제한(추가 배치물)이 오면 "좌표-전용 배치물 맵" 공통화를 그때 1회 리팩터로. 지금 하면 신호까지 껴서 추상화가 어중간해짐. 최종리뷰 Minor 이월 목록에 기록 |
| 3자 배타 | 신호/로터리/입체는 한 타일에 하나 | 한 타일 한 장치(로터리 규약 연장). CanPlace 3종이 서로의 셋을 확인 |
| 배치 모드 전용·소멸·좌표만 저장 | 로터리와 완전 동일(AutoDetectSignals=false, 교차로 해제 시 소멸, optional 배열, 구세이브 null) | 동형 규약 유지 — 설명 비용 0 |
| 이벤트 없음·마커 폴링 | `OverpassTiles` 폴링 | 신호·로터리와 동일. YAGNI |

## §1. FlowSolver — 네 갈래 분기

무신호 교차로 루프(①'')가 최종형이 된다: 신호 있음 → 스킵(①'가 처리) / **입체 있음 → `ratioH=fH/C, ratioV=fV/C`** / 로터리 있음 → λr·cf 수식 / 둘 다 없음 → λ=1.5. Resolve 시그니처에 `overpasses`(HashSet, null 허용)를 roundabouts 옆에 추가, 기존 오버로드는 null 위임 체인 연장(기존 테스트 무수정 생존). 결정론: 셋은 조회만, 순회는 grid 스캔 불변.

Config 추가 없음 — 입체교차는 계수가 없다(간섭 0·페널티 0이 정체성). 🔓 밸런스 노브가 필요해지면 그때 추가(YAGNI).

## §2. SimEngine — 배치 API + 세이브 + 계약

- `_placedOverpasses` List(flat 정렬)+`_overpassSet` — 로터리와 동형.
- `CanPlaceOverpass(tile)` = 배치 모드 && 교차로 && 3자 미배치. `CanPlaceSignal`/`CanPlaceRoundabout`에 `&& !_overpassSet.Contains(tile)` 추가.
- `TryPlaceOverpass(tile)` / `TryRemoveOverpass(tile)` — Rebuild 불필요(SignalMap 무관, 로터리와 동일).
- 재구축 블록(RebuildSignals): 교차로 해제 시 소멸 프루닝 3벌째 추가.
- 세이브: `SimSaveData.Overpasses`(`OverpassSaveData[]` — X,Y만, optional). RestoreSnapshot 배치 모드 블록에서 클리어→재구성→flat 정렬(로터리 블록과 나란히).
- 계약: `ISignalControl`에 입체 4종(`OverpassTiles`/Can/TryPlace/TryRemove) 제안 누적 — 김건 합의 대상. (제안이 12종까지 늘어남 — 배치물 공통 계약으로의 분리 제안도 주석에 한 줄 남김)

## §3. 뷰 — 마커만 (MainCityView)

가로 바(위, z 살짝 앞) + 세로 바(아래) 두 직사각형으로 "위아래 분리"를 암시하는 마커. `OverpassTiles` 폴링, 로터리 마커와 동일 수명 규약. 차량 연출 변화 없음(직진 그대로 — 위/아래 구분은 에셋 단계 후속, 비목표).

## §4. 테스트 (EditMode — OverpassTests)

Task 2에서 확립한 원칙 재사용: **시나리오 간 흐름 동일**(라우팅 신호 무관) 성질로 비교하고, 다목적지 수요 오염이 불가능한 기하를 쓴다.

1. 배치/철거/3자 배타(신호↔로터리↔입체 상호 거부)/교차로 해제 소멸/flat 정렬 — 로터리 스위트 동형
2. **사슬 핀**: 검증된 십자(BuildCross 6/6, d=1.5, greenSlots=9)에서 `무신호 < 신호 < 입체교차` — 입체 교차로 ratio H 0.75·V 0.625로 병목이 간선(1.5/1.25)으로 완전 이동 → 신호(학교축 1.4286)를 엄격히 이김
3. **정체성 핀(무페널티)**: 무교차 기하(NoCrossTraffic)에서 `입체 delivered == 무신호 delivered` **완전 동률**(AreEqual) — 로터리(용량 페널티로 손해)와 정확히 대비되는 입체교차의 존재 증명. fV=0이면 기본 합산 `(fH+0)/C`와 축 독립 `fH/C`가 같은 값 → 결정론상 비트 동일
4. 로터리 vs 입체 직접 비교는 **안 넣는다** — 균형 십자에선 둘 다 병목이 간선으로 빠져 동률(간선 마스킹, Task 2 실측 교훈). 관계 서술은 §핵심결정 "상위호환은 의도"가 담당
5. 세이브 라운드트립 + 구세이브(필드 없음) + 결정론
