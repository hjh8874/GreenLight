# 설계 — 회전교차로 (교차로 3형제 완성)

> 작성: 2026-07-11 (환과 브레인스토밍 — 범위·수학 프레임·표현 방식 합의 완료). 짝 계획: writing-plans로 후속.
> 선행 스택: 축분리 ← 파밍가드 ← 라우팅 ← 차량겹침 ← 신호배치. 브랜치 `feat-roundabout-hwan`.
> 배경: dev-log-12 다음 구매템 1순위. 무신호 λ 수학(1단계)과 배치 인프라(신호배치)를 재사용해 "교차로 3형제"(무신호/신호/로터리)를 완성한다.

## 목표 / 스코프

**회전교차로 = 교차로에 배치하는 세 번째 상태.** 낮은 간섭(λ=0.25) + 용량 페널티(×0.7)의 무신호 교차로로 근사한다. 엔진(수식+배치 API+세이브) + 뷰(마커+차가 도는 연출)까지 이번 범위. 가격·상점 UI는 팀 몫(신호와 동일 분업).

## 핵심 결정 (근거 포함)

| 결정 | 내용 | 근거 |
|---|---|---|
| **용량 페널티 모델** | `ratio축 = (내축 + λr×교차축) / (용량×cf)`, λr=0.25, cf=0.7 | 상수 λ만 쓰면 λ<1인 이상 최적 신호를 **항상** 이겨 전략 선택이 죽음(수학 §1). cf<1이 "로터리는 주축도 감속" 현실을 담아 균형을 만든다 |
| **전략 축 = 흐름 균형** | 균형 교차로(작은축/큰축 > 2/3)=로터리 승, 편중(0.375~2/3)=신호 승, 극단 편중(<0.375)=무신호가 로터리보다 나음 | 선형 모델이라 절대량으론 승자가 안 바뀜 — 균형이 전략 축. 플레이어가 화면에서 읽을 수 있는 휴리스틱. 절대량 붕괴(현실 포화)는 필요 시 λ 부하 비례 한 줄로 후추가 |
| 상태 표현 = 배치 리스트 병렬 | SimEngine에 `_placedRoundabouts` — 신호 배치 3종과 동형. SignalMap·TileType 불변 | Signal 구조 확장은 신호 전용 필드(오프셋·오버라이드)가 무의미해지고 코리도어가 로터리를 신호로 착각할 함정. 타일 타입 신설은 라우팅 전반에 파문 — 과함 |
| 신호와 배타 | `CanPlaceRoundabout` = 신호 없는 교차로만, `CanPlaceSignal`도 로터리 있으면 false. 교체 = 철거 후 배치 | 한 타일 한 장치. 환불/교체 보상은 경제(진우) 영역 — 신호와 동일 철학 |
| 배치 모드 전용 | `AutoDetectSignals=false`일 때만 배치 가능 | 자동 모드는 모든 교차로에 신호 = 자리 없음. 라이브 잠복 스케줄도 신호 배치와 동일(상점 UI 붙는 날 함께 개방) |
| 조율값 없음 | 로터리는 좌표만 저장 — 오프셋/초록/오버라이드 없음 | "조율 안 해도 흐르는 것"이 로터리의 정체성. 코리도어 버스트·그린웨이브 로직은 로터리를 아예 안 봄(신호가 아니므로 자연히 배제) |
| 이벤트 없음 | 배치/소멸 이벤트 미발행 — 뷰는 `RoundaboutTiles` 폴링 | 신호 마커(RefreshSignals)와 동일 패턴. YAGNI |

## §1. 수학 — 왜 이 계수인가

신호 최적(g를 완벽 조율)의 병목 하한 = `(가로+세로)/용량`. 상수 λ<1 로터리 = `(큰축+λ×작은축)/용량`은 이보다 항상 작다 → 로터리가 신호 상위호환 = "노드 전략 선택" 붕괴. cf=0.7을 나누면, s = 작은축/큰축에 대해:

- 로터리 < 신호최적 ⟺ `s > (1−cf)/(cf−λr)` = 0.3/0.45 = **2/3**
- 무신호 < 로터리 ⟺ `1+1.5s < (1+0.25s)/0.7` ⟺ **s < 0.375**

→ 균형=로터리 / 중간 편중=신호 / 극단 편중=방치가 각각 최적인 3분할. 계수는 SimConfig `RoundaboutInterference=0.25f`, `RoundaboutCapacityFactor=0.7f`(UnsignaledInterference 옆, 추후 SO 튜닝 대상).

## §2. FlowSolver — 세 갈래 분기

무신호 교차로 루프(①'')에서: 신호 있음 → 스킵(①'가 처리, 현행). **로터리 있음 → §1 수식**. 둘 다 없음 → 현행 λ=1.5. Resolve 시그니처에 로터리 셋(`HashSet<Vector2Int>`, null 허용)을 signals·grid와 나란히 전달 — 엔진 소유 셋을 그대로 넘기므로 동기화 코드 없음. 결정론: flat 순회 순서 불변(셋은 조회만, 순회는 grid 스캔).

## §3. SimEngine — 배치 API + 소유 + 세이브

- `_placedRoundabouts` List(flat 정렬)+HashSet — `_placedSignals`와 동형.
- `CanPlaceRoundabout(tile)` = 배치 모드 && 교차로 && 로터리 미배치 && **신호 미배치**. `CanPlaceSignal`에 `&& !로터리` 추가.
- `TryPlaceRoundabout(tile)` / `TryRemoveRoundabout(tile)` — 신호 3종과 동형. 단 로터리는 SignalMap 무관 + FlowSolver가 엔진 소유 셋을 직접 보므로 **Rebuild 트리거 불필요** — 리스트/셋 갱신이 전부.
- 재구축 블록: 도로 철거로 교차로 해제 → 로터리 자동 소멸(신호와 동일 흐름).
- **세이브**: `SimSaveData`에 optional `Roundabouts`(좌표 배열) 추가. 구세이브 null → 로터리 0개, 마이그레이션 불필요. RestoreSnapshot에서 배치 모드일 때 flat 정렬 재구성(신호 복원 흐름과 동형).
- **계약**: `ISignalControl`에 로터리 3종 + `RoundaboutTiles`(뷰 폴링용) **제안 누적** — 김건 합의 대상 목록에 추가.

## §4. MainCityView — 마커 + 차가 도는 연출

- **마커**: `RoundaboutTiles` 폴링 → 원형 마커 생성/제거. `RefreshSignals`/`SignalVisual` 패턴 복제(RefreshRoundabouts).
- **도는 연출**: 차량이 로터리 타일을 지나는 구간만 직선 보간 대신 **타일 중심 기준 반시계 원호**(우측통행)로 위치 계산. 기존 차선 오프셋(laneOffset) 위에 얹는 뷰 전용 수학 — 엔진 무관, 결정론 무관.

## §5. 테스트 (EditMode — RoundaboutTests)

1. 배치/철거/배타(신호↔로터리 상호 거부)/교차로 해제 시 자동 소멸
2. 수식 3분할 검증: 균형 흐름에서 로터리 ratio < 신호최적 < 무신호 / 편중에서 신호 승 / 극단 편중에서 무신호 < 로터리
3. 세이브 라운드트립 + 구세이브(Roundabouts 없음) 호환
4. 결정론: 같은 입력 = 같은 delivered (기존 관례)

뷰(§4)는 Play 프로그래매틱 검증 — 비포커스 에디터는 `isPaused=true`+`Step()` 펌핑(기술노트 2).
