## 배경 / 왜

현행 길찾기는 BFS 최단 홉 단일 경로, 혼잡 무시:
- **평행 도로 분산 없음** — 동률이어도 이웃 스캔 순서로 한 줄에 전부.
- **우회로 무시** — 1칸이라도 길면 절대 안 씀. "막히니까 돌아간다"가 존재하지 않음.
- 결과: 유저가 정체 해소용 우회로를 놓아도 아무도 안 씀 → "버그 망겜" 체감(외부 피드백·자체 진단 일치). 교통 게임의 핵심 수(건설로 정체 해소)가 죽어 있음.

## 결정 기록 (2026-07-11 환)

| 결정 | 내용 |
|---|---|
| 세계관 | **유기적** — 길을 놓으면 차들이 알아서 나눠 탐(분산이 창발). 통제 툴(일방통행/진입금지)은 장기 옵션으로 보류 |
| 알고리즘 | **증분 탐욕 배정** — 수요를 고정 순서로 하나씩, 앞 수요의 부하를 피해 Dijkstra. 균형 반복(오버킬)·k-분할(수요당 경로 1개 구조 파괴) 기각 |
| 거리 | **물리 거리** — 직각 1, 대각 √2. 경로 선택이 그린웨이브 타이밍(SignalFactor의 √2)과 처음으로 일치 |
| 재배정 트리거 | **topology 변경만**(배치/철거). 신호 레버·오버라이드·맥동은 트리거 아님 — 오프셋 튜닝 중 경로가 출렁이면 그린웨이브 퍼즐 붕괴. "차들은 습관대로, 건설이 습관을 바꾼다" |
| 회피 강도 | `RoutingCongestionWeight = 2` 🔓 (SimConfig 신설) |

## §1. RoutePlanner (신규 유닛, `Sim/RoutePlanner.cs` internal)

재건축 시(TopologyDirty 소비 시점) 1회 실행. 입력: 수요 목록(DemandMap 순서 = 결정론)·grid·접점 조회·cfg. 출력: **수요별 경로 테이블**(`IReadOnlyList<List<Vector2Int>>`, 수요 인덱스 정렬, 미연결 = null).

알고리즘 (증분 탐욕):
1. 부하 맵 `load[타일]` 0으로 시작.
2. 수요 i의 경로 = Dijkstra, **스텝 비용 = 물리거리 × (1 + w × load[도착타일] / RoadCapacity)** (w = `RoutingCongestionWeight`).
3. 찾은 경로의 각 타일에 `load += DemandPerHouse`(맥동 무반영 — 평균 기준. 정산 철학과 동일) 적립 → 다음 수요가 회피.
4. 결정론: 고정 수요 순서 + Dijkstra 타이브레이크 = (비용, flat index) — 같은 도시 = 같은 경로 테이블. 20×20 규모라 단순 배열 스캔 Dijkstra로 충분(힙 불요, 틱 중 아님이라 할당 허용).

이웃/연결 규칙은 기존 BFS와 동일(8방, 코너컷 허용). **대각 코너컷은 유지** — √2(1.41) < 직각 2라 물리적으로도 정직하게 짧음. 혼잡 비용이 붙으면 막힌 교차로를 대각으로 돌아가는 게 자연히 더 매력적 — 리얼.

## §2. 배선 변경

- `SimEngine.Step`·`SettleOffline`의 TopologyDirty 재구축 블록: `_network.Rebuild()` → `_demand.Reassign(...)` → `_signals.Rebuild(...)` 다음에 **`_planner.Plan(...)`** 추가.
- `FlowSolver.Assign`: `net.FindPath(from,to)` 대신 **계획된 경로 테이블을 인덱스로 읽음**(시그니처 변경). 매 틱 dict 캐시 조회가 사라져 오히려 쌈. 미연결(null) 스킵 규약 유지.
- `RoadNetwork`: `FindPath`/`Bfs`/경로 캐시 **은퇴(삭제)** — 소비자가 FlowSolver뿐(확인 완료). `RegionOf`(도달성)·`TryGetAccessRoad`(접점)는 유지 — DemandMap·RoutePlanner가 사용.
- `RoadNetworkTests`의 경로 단언 8건은 RoutePlanner 테스트로 이관(물리 거리 기준 기대값 재검토 — 순수 대각 경로는 물리적으로도 최단이라 대부분 유지).

## §3. 파라미터 (SimConfig)

| 필드 | 값 | 의미 |
|---|---|---|
| `RoutingCongestionWeight` (신설) | **2** 🔓 | 회피 강도. 0 = 순수 물리 최단. 2면 부하율 1.5 타일이 4배 비쌈 → 몇 칸 우회가 이득. asset+Default 둘 다 |

## §4. 화면에서 바뀌는 것

- 평행 도로를 놓으면 차들이 **나눠 탐**(지금: 전부 한 줄).
- 붐비는 간선 옆 우회로에 **일부가 돌아감**(지금: 무시) — "내가 뚫은 길을 쓴다".
- 빈 도시 경로도 소폭 변화(대각 남용 감소 — 물리 거리 정직화).
- 재배정은 건설/철거 때만 → 차들이 이유 없이 단체 유턴하는 일 없음.

## §5. 파급 (의도된 변화, 명시)

- 기존 delivered/경로 의존 테스트 일부 값·경로 변경 예상(대각 비용 변화) — 축분리 S-테스트는 직진·코너컷 기하라 대부분 생존 예상, 검증 필요. DeterminismTests는 해시 값이 바뀌어도 결정론 자체(두 실행 동일)는 불변이어야 함.
- SignalFactor(그린웨이브)·병목 판정은 경로에서 재계산되므로 자동 정합 — 코드 무변경.
- 차량 뷰(`Routes`)는 수요당 경로 1개 구조 그대로.

## 검증 계획 (EditMode)

- **평행 분산**: 같은 길이 도로 2개 + 수요 2 → 경로가 갈라짐(각 도로 1개씩).
- **우회 흡수**: 간선(짧음)+우회로(몇 칸 김) + 간선을 포화시키는 수요 → 뒤 수요 일부가 우회로 사용, delivered가 우회로 없을 때보다 증가.
- **빈 도시 물리 최단**: 대각 지그재그보다 직선 선호(√2 반영), 순수 대각 연결은 대각 유지.
- **결정론**: 같은 도시 2회 계획 = 같은 경로 테이블·delivered.
- **미연결**: null 경로 스킵(기존 규약).
- 기존 스위트(117) 영향 리뷰 — 경로 변화분만 갱신, 원인 명시.
