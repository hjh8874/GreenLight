# 설계 — 고속도로 (MM식 2램프 직결, 환 트랙)

> 작성: 2026-07-21 (환 브레인스토밍 확정). 짝 계획: writing-plans로 후속.
> 배경: 차기 교통 요소 리서치(개인 위키 `idle-city-traffic-feature-research`)에서 결정 —
> 타 게임 분석 결과 물리 도구(교차로 4형제·일방·예산)는 완성돼 있고, 빠진 것이 장거리 직결.
> MM에서 가장 사랑받는 업그레이드이며 현실 개념 설명이 0초("고속도로").

## 목표 / 스코프

**램프 두 칸을 놓으면 그 사이가 고가로 직결되는 고속도로.** Sim 링크 큐 + 라우팅 간선 +
배치/철거 API + 세이브 + 폴리라인 고가 세그먼트 + 마커 비주얼까지 이번 범위.
구매 UI는 진우 몫(로터리·입체교차와 동일 분업), 고가 에셋 그래픽은 후속(비목표).

## 핵심 결정 (브레인스토밍 확정 3건 + 파생)

| 결정 | 내용 | 근거 |
|---|---|---|
| **형태 = 2램프 직결** | 도로 타일(교차로 제외) 두 곳에 램프A·B 설치 → 사이가 임의 각도 고가 직선으로 연결. 중간은 건물·도로 위 통과(간섭 소멸 — 입체교차 원칙의 연장) | 타일식 고속도로는 고속도로끼리/일반도로와의 교차 문제를 재생산 → 기각. MM 검증 패턴 |
| **경제 = 코인 구매 + 도로 예산 편입** | 구매가 = 거리 비례 코인(`IEconomyService.TrySpend`), 링크 길이만큼 도로 예산(`MaxRoadTiles`) 소모 | ⚠️ 정정(2026-07-21 코드 조사): 유지비 체인(`RoadMaintPerSec`)은 삭제된 dead chain — 현행 도배 방지 장치는 **도로 예산제(스톡 상한)**. 고속도로도 같은 예산을 먹게 해 "예산을 고속도로에 쓸까 일반도로에 쓸까" 결정을 만든다 |
| **정체 = 출구 스필백** | 링크 자체는 신호 없이 흐름. 진출 램프 앞 일반도로가 만석이면 링크 위에 줄이 섬(용량 = 거리 비례) | "정체=순손실" 기둥과 정합. 출구 주변 설계라는 2차 퍼즐 생성. 절대 안 막힘 모델은 도배 익스플로잇 재개방 위험 → 기각 |
| 방향 = 양방향 | 램프 쌍 = A→B, B→A 링크 큐 2개 | 단방향 쌍 강제는 UX만 복잡 |
| 탑승 = 자동 라우팅 | 경로 그래프에 램프 간선 추가(비용 = 통과 틱 + 혼잡 페널티). 유저는 차를 지정하지 않음 | 기존 혼잡 회피 라우팅 재사용. 링크가 차면 비용 상승 → 일반도로 재분산까지 자동 |
| 배치 제약 | 램프는 일반 도로 타일 위(교차로 불가), 두 램프 최소 5타일 | 교차로 램프는 중재와 얽힘. 최소 거리 없으면 1타일 점프 악용 |

## Sim 구조 (전부 환 소유 파일)

- **링크 = FIFO 지연 큐**: 진입 시 통과 시간(거리 ÷ 고속도로 속도, 틱) 부여, ETA 순 진출. 추월 없음.
  - 선형 체인 → 기존 "정지 관계는 선형뿐 = 사이클 불가" 데드락 논증 그대로 적용.
  - 용량 = 거리 비례(타일당 1대 수준, 🔓 밸런스).
- **진입**: 램프 타일 큐 헤드가 `HighwayEntry` 인텐트 — 로터리 `RingEntry` 패턴 재사용. 만석이면 대기(+`_blockedTicks`).
- **진출**: ETA 도래한 링크 헤드 → 램프B 타일 큐 `CanAcceptNormally` — 실패 시 대기 = 스필백.
  출구는 일반 그리드(교착 밸브 보장) → 링크는 반드시 드레인.
- **라우팅**: 램프A↔B 간선. 비용에 링크 점유율 페널티 포함(혼잡 회피와 동일 함수형).
- **세이브**: 링크 목록(램프 쌍) + 링크 위 차량(노드·ETA). `save-load-naming-contract.md` 준수.
- **경제**: 유지비는 기존 도로 유지비 파이프에 거리×단가 항 추가. `SimConfig` 필드(단가·속도·용량 계수)는
  **담당자에게 요청**(소유권 계약 금지사항 3 — Default()와 .asset 3개 동기화).
- **배치 API**: `CanPlaceHighway / TryPlaceHighway / TryRemoveHighway` — `SimEngine` 로터리 배치(환 구역) 패턴 그대로.

## 기하·뷰 (환 소유 + 경계 계약 1건)

- `RoutePolyline` 고가 세그먼트: 램프A 상승 전이 베지어 → 직선(Z 상승) → 램프B 하강 전이.
  로터리 전이 베지어(`AppendTransitionBezier`) 재사용.
- **`BakeInput` 고속도로 필드 추가 = 주석 통지 필수** (소유권 문서의 환↔주석 유일 접점. 머지 전 공유).
- 링크 위 차량 `CarSnapshot` 위치 = 링크 진행률 노출(`TryLocateCar` 확장) → 뷰 코리도 무수정 작동이 목표.
- 비주얼: 고가 상판·기둥 마커 수준(입체교차 방식). **전용 루트에 부착** — `signalRoot` 부착 시
  준희 `ClearChildren`에 함께 소멸하는 문서화된 사고 회피.
- 렌더: 고가 위 차량이 아래 차량·건물 위에 그려지는 소팅(Z) 확인.

## 검증 게이트

1. EditMode: 링크 FIFO 순서 보존 · 용량 만석 진입 거부 · 출구 만석 스필백 · 라우팅이 더 빠를 때만 선택 ·
   세이브 왕복(링크+링크 위 차량) · 배치/철거 규칙(교차로 불가·최소 거리).
2. 계측 회귀: 기존 겹침/정지 하니스에서 악화 없음(고속도로 1개 설치 상태로 재측정).
3. 라이브: hwan 씬 육안 1회 — 램프 전이 기하(상승/하강 헤딩), 고가 위 정지(스필백) 그림.

## 유저 경험 요약 (한 줄 흐름)

간선이 막힌다 → 주거 근처·회사 근처에 램프 설치 → 통근 차가 고가로 빠져 아래가 풀린다 →
출구 주변이 새 병목 → 거기를 다듬는 게 다음 퍼즐.
