## 1. 건설 시 순간이동 — 계측 재현 ✅

**재현 절차**: 주행 7대 상태에서 `IPlacementService.Place((1,3), Road)` 호출 → 2.5초 관찰.

**결과**:
```
배치 0.52초 후 (= 다음 심 틱): 4대가 한 프레임에 1타일 이상 점프
  car15 Outbound->Inbound  5.90타일
  car3  Inbound ->Inbound  1.68타일
  car4  Inbound ->Inbound  1.27타일
  car8  Inbound ->Inbound  1.10타일
주행->주차 강제전환 3대 / 17대
점프는 1.84초·2.51초 후에도 반복(1.20타일)
```

**코드 기전** (확정):
- `CarSim.Rebuild` 마지막 줄 `_needsSnap = true` (CarSim.cs:99)
- 같은 틱의 `Step`이 소비 (CarSim.cs:119-126): `net.RemoveAllCars()` + `_scheduler.SnapToHour(gameHour)` + `Array.Fill(_queueSlots, -1)`
- `SnapToHour`는 **전 차량**을 `ParkedHome/ParkedWork`·`Distance=0`으로 되돌림 (CommuteScheduler.cs:150-177)
- 이걸 막으려 만든 **`SnapNewToHour`(신규 차만 수렴, :159)는 호출자 0건** — 주석(:24, :67, :179)에만 이름이 등장. 의도가 배선되지 않음.

⚠️ **주의**: 계측은 17대 중 3대만 주차 전환을 보였다(전원 아님). `UpdateDepartures`가 같은/다음 틱에 즉시 재출발시켜 잔여만 관측됐을 가능성이 큼. **"전원 스냅"은 코드 근거, 관측된 것은 그 결과의 일부** — 이 구분을 유지할 것.

## 2. 교차로 겹침 — 계측 확정 ✅

**계측**(479프레임, 17대):
```
간격<0.20타일 쌍 분류
  같은경로·같은타일·같은슬롯 (Sim 이중배정): 0
  같은경로·다른슬롯/타일   (뷰 기하 과포화): 0
  다른경로                (교차 고스트)   : 76   ← 100%
예: car3(route3,tile7,slot0) vs car8(route8,tile5,slot0) — 간격 0.000
```

**구조적 원인**: Sim의 큐 키는 **(타일, 진입방향)** — `queue = tileIndex * 4 + entry` (RoadQueueNetwork.cs:154). 한 타일에 방향별 큐 4개.
뷰의 위치 키는 **(경로, 경로내 타일인덱스, 슬롯)** — `DistanceAtQueueSlot(tileIndex, queueSlot, ...)`에 **진입 방향 인자가 없음** (RoutePolyline.cs:208).

→ 서로 다른 방향에서 같은 타일에 든 두 차가 각자 자기 큐의 slot 0을 쥐고, 뷰는 둘 다 "그 타일의 머리"에 그린다. 교차로에서 정확히 좌표가 일치.

**이것이 "미세 조정으로 안 되는" 이유**: Sim이 차를 구분하는 축(진입 방향)을 뷰가 버리고 있음. 파라미터가 아니라 **계약의 문제**.

> 참고: Sim은 정원을 정확히 지킨다(`CanAcceptNormally`, :508). 이중배정 0건이 이를 뒷받침.

## 3~8. 코드 확정, 조건부 발현

- **3. 클램프 off-by-one** — `maxSlotGap = (tileSize - headInset) / (capacity - 1)` (MainCityView.cs:2004). 분모가 `capacity-1`이라 마지막 슬롯이 정확히 1타일 뒤 = **상류 타일 slot0과 좌표 일치**. 발현 조건 = 한 방향 큐 만석(4) + 상류에 1대 이상.
  ⚠️ 이번 계측(17대·경정체)에서는 같은경로 겹침 0건 — **잠재 결함이며 현재 눈에 보이는 겹침의 원인은 아니다.** 정체가 커지면 발현.
- **4. 코너 압축** — `cornerTurnRadius 0.6`이면 코너 타일의 실제 호 길이 = 0.871타일인데 뷰는 슬롯 거리를 상수 1.0으로 계산 → 하류 tail이 상류 head보다 0.129타일 뒤 = 순서 역전.
- **5. 교착 밸브** — `Force`가 `CanAcceptNormally`를 우회(RoadQueueNetwork.cs:385), `AppendNode`(:528)에 상한 가드 없음 → `_counts > _capacity` 가능. 슬롯 4+ 는 타일 밖으로 밀려나고, 경로 앞부분이면 `Clamp(0, Length)`가 **0 = 집**으로 만든다. **발동 빈도 미측정.**
- **6. 렌더러 off 3곳** — MainCityView.cs:1732 / :1742 / :1911. 셋 다 `activeSelf`는 true로 남아 `TakeFreeVehicle`(:1778)이 재사용하지 못함 → **보이지 않으면서 풀 슬롯 점유**. (계측: 8초에 활성토글 3회 관측)
- **7. `previousBakes` 키 오류** — `SyncCarSimMirrors`(:1394)가 `RebuildCommute`(:1414)보다 먼저 돌아 `RouteIndex`가 이미 새 값인데, :1476이 그 새 값으로 옛 베이크를 조회. `RebakeCommuteGeometry` :1492에 같은 버그 복제.
- **8. `QueueSlot<0 → 0f`** (:2006) — `DistanceAtQueueSlot`은 이미 `Mathf.Max(0, queueSlot)`으로 음수에 안전(RoutePolyline.cs:216). 특수분기가 올바른 타일 머리 위치를 버리고 0(=집)을 반환. **단독 발현은 제한적이나 1·5의 피해를 집까지 확대하는 증폭기.**
  계측 확인: `QueueSlot<0`은 `ParkedWork`에서만 발생(11/11), **주행 중 0건** → 단독으론 현재 미발현.

## 폐기된 가설 (기록)

- ❌ "`QueueSlot<0 → 0f`가 사라짐의 주범" — 최초 내 가설. 계측 결과 주행 중 발생 0건으로 **반증**. 증폭기이지 방아쇠가 아님.
- ❌ "겹침은 주차 기하(회사 앞) 때문" — 계측상 `ParkedWork×ParkedWork`는 6회·최소 0.208타일로 경미. 주행 차량 간 겹침이 압도적.
- ❌ 과거 감사의 "`QueueCapacityPerTile` 3이면 간격 0.44로 완전 해소" — `slotGap = min(followGap*tileSize, ...)`의 0.4 상한이 먼저 걸려 실제는 0.4. 최대 차 길이 0.437보다 작아 **완전 해소 아님**.

## 밸런스 결정 필요 (환/준희)

타일 1.0에 길이 0.38(최대 0.437, 브레이크등 포함 실효 0.407~0.468)짜리 차를 겹치지 않게 넣으려면 **N ≤ 2.3**.
- `QueueCapacityPerTile = 2` → 완전 해소, 도로 처리량 −50%
- `= 3` + 차체 길이 0.38→0.29(−24%) → 해소
- `= 4` 유지 → 길이 0.217(−43%) 필요, 시각적으로 과함
